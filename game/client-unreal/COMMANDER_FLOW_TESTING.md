# التحقق من مسار القادة

يستبدل هذا التحديث قائمة القادة المحلية التجريبية بمزامنة مصادق عليها مع `/v1/commanders`. كما يجعل كل بطاقة قابلة للنقر وتفتح القائد الصحيح، ويصل أزرار رفع المستوى والمهارة بطلبات الخادم السلطوي.

## الفحوص الآلية المتاحة

من مجلد `game/backend` شغّل:

```bash
npm run check
```

يشغّل الأمر فحص TypeScript، وجميع اختبارات قواعد اللعب الأوفلاين، وفحص عقد عميل القادة. يفحص الاختبار الأخير تطابق مسارات وحقول العميل مع الخادم، وعدم عودة القائمة التجريبية أو ربط جميع البطاقات بأول قائد.

## اختبار القبول داخل Unreal

| الخطوة | السلوك المقبول |
|---|---|
| تسجيل الدخول بلاعب عائد | تُحمّل قائمة القادة المملوكين من الخادم، ولا تظهر أسماء تجريبية غير مملوكة. |
| تأسيس مدينة جديدة | يظهر قائد البداية بعد اكتمال `/v1/city/init` ومزامنة القادة. |
| اختيار بطاقة | تتغير لوحة التفاصيل للقائد الذي اختاره اللاعب، وليس لأول قائد في القائمة. |
| رفع المستوى | لا يُرسل الطلب ما لم يملك اللاعب تومة واحدة على الأقل؛ وعند نجاح الخادم تتجدد القائمة والتفاصيل. |
| رفع مهارة | يختار العميل أول مهارة مؤهلة بحسب مستوى القائد، ثم يعيد المزامنة بعد رد الخادم. |
| إرسال مسيرة بقائد | يستخدم العميل الحقل `primaryCommanderId` الذي يقرأه الخادم. |

## قيد التحقق في هذه البيئة

لا توجد أدوات بناء Unreal Engine في بيئة العمل الحالية، لذلك لم يُنفَّذ بناء أو تشغيل Unreal هنا. هذه ليست نتيجة بناء فاشلة؛ بل خطوة قبول لازمة على جهاز يحتوي إصدار المحرك المحدد في `UNREAL_ENGINE_GUIDE.md`. تظل فحوص TypeScript وقواعد اللعبة وفحص عقد العميل قابلة للتنفيذ وقد اجتازت محلياً.

> لا يتضمن هذا الفرع نشر خادم أو تغيير أسرار أو هجرات قاعدة بيانات. يبقى النشر إلى بيئة الاختبار خطوة منفصلة بعد فحص Unreal اليدوي.
