# P7-T5 — استعادة الحالة وإعادة الاتصال في العميل

## الهدف

بعد عودة اتصال WebSocket حي انقطع سابقاً، يعيد العميل بناء حالته من **المصدر السلطوي للخادم** بدلاً من متابعة عرض محلي قديم. لا يغيّر هذا المسار حالة اللعب أو يسجل أوامر؛ إنه مجموعة طلبات قراءة فقط تنتهي ببث الواجهات القائمة وراسم العالم من جديد.

> لا تُعد الاستعادة بديلاً عن تسجيل الدخول الأولي. يبدأ اللعب لأول مرة بمسار التهيئة العادي، وتُطلق الاستعادة فقط عند عودة اتصال WebSocket كان حياً ثم انقطع.

| مصدر الحالة | نداء القراءة | المستهلكون الرئيسيون |
|---|---|---|
| المدينة والطوابير والموارد | `GET /v1/city` | `Rok2CityWidget` وHUD |
| العالم والمسيرات والموسم والقصة | `GET /v1/world/snapshot` | `Rok2WorldRenderer` وHUD وSeason Story |
| القادة | `GET /v1/commanders` | واجهات القادة والمدينة |
| تقارير القتال الخاصة | `GET /v1/combat/reports` | `Rok2BattleReportWidget` وHUD |
| راليات التحالف | `GET /v1/alliance/rallies` | لوحة الراليات وHUD |
| الدردشة | رسالة `chat_history` بعد `hello` عبر WebSocket | `Rok2ChatWidget` |

## سلوك العقد

تدير `URok2Api::RestoreAuthoritativeState()` دورة الاستعادة. يضمن المزلاج `bStateRestoreInFlight` أن تذبذب الشبكة لا يطلق دورتين متوازيتين، ويضمن العداد أن كل طلب من الحزمة الخماسية ينهي الدورة سواء نجح أو بلغ فشله النهائي. عند اكتمالها يظهر إشعار **«اكتملت المزامنة»** وتبقى البيانات الناجحة التي وصلت من الخادم هي المعروضة.

تعيّن أخطاء أو إغلاقات WebSocket راية استعادة فقط إذا كان الاتصال **حياً بالفعل** وكان اللاعب معتمداً وما زالت إعادة الاتصال مرغوبة. يمسح `DisconnectWebSocket()` هذه الراية والمزلاج والعداد، لذلك لا يمكن أن تستعاد جلسة بعد فصل يدوي أو خروج اللاعب.

يستمر `Rok2WorldRenderer` في استهلاك بث `OnWorldSnapshot` القائم، والذي يعيد مزامنة كيانات المسيرات والمدينة من لقطة سلطوية؛ لا تُضاف طبقة actors أو cache ثانية في P7-T5.

## الحارس البنيوي

```bash
cd game/backend
npm run test:reconnect-restore
```

يتحقق الحارس من وجود الحزمة الخماسية، ومسارات النجاح والفشل، ومزلاج منع التوازي، وشرط إعادة الاتصال، وإزالة حالة الاستعادة عند الفصل اليدوي. يدخل ضمن `npm run check`.

## قبول PIE المطلوب لإغلاق البند

يشغّل هذا الإجراء على Windows مع UE **5.4.4** بعد بناء المحرر بنجاح. لا يمكن تنفيذه في بيئة Linux الحالية.

1. شغّل عميلين أو PIE بنافذتين وسجّل دخولهما بحسابين مستقلين.
2. في أحد العميلين افتح المدينة، أرسل مسيرة، افتح الدردشة والتقارير والراليات، ثم اترك الخادم يدفع لقطة عالم.
3. اقطع الشبكة الحية للعميل المستهدف مؤقتاً أو أوقف خادم الاختبار، وتحقق من ظهور حالة إعادة المحاولة من دون عمليات لعب محلية.
4. أعد الاتصال. يجب أن يظهر إشعار **«اكتملت المزامنة»** مرة واحدة فقط، وتُستعاد المدينة والطوابير والمسيرات والقصة والتقارير والراليات والدردشة من الحالة الخادمية.
5. كرر القطع والعودة ثلاث مرات. راقب World Outliner أو أدوات التشخيص: لا actors مسيرات مكررة، ولا عدادات قديمة، ولا طلبات استعادة متوازية.
6. افصل يدوياً أو اخرج من الحساب ثم أعد فتحه. لا يجوز أن تعمل دورة الاستعادة القديمة؛ يبدأ مسار التهيئة الصحيح للحساب الجديد.

سجّل رقم بناء المحرر والبيئة ولقطات القبول في `PLAN.md` عند تنفيذ هذه الخطوات. يبقى P7-T5 `[ ]` إلى ذلك الحين.
