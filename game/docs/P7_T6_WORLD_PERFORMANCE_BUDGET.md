# P7-T6 — خط أساس أداء خريطة العالم وميزانية Android

**الحالة:** منفذ برمجياً؛ يبقى قبول جهاز Android فعلياً شرطاً لإغلاق البند.

## الغرض

يوفر هذا البند طريقة ثابتة لالتقاط تكلفة تمثيل خريطة العالم في PIE أو في حزمة تطوير Android. لا يغير قواعد اللعب ولا صورة الموسم أو حدود الخادم. يلتقط العميل أعداد عناصر العرض التي يديرها `ARok2WorldRenderer`، ونافذة زمن `Tick` الخاصة بهذا الراسم، فيما تحفظ أوامر القياس القياسي في Unreal بيانات الإطار والذاكرة وGPU من الجهاز المستهدف.

> لا يمثل `WorldFrameAverageMs` أو `WorldFramePeakMs` زمن إطار اللعبة الكامل ولا زمن GPU. إنهما يصفان `DeltaSeconds` المرئي لراسم العالم فقط، ولذلك يجب قراءتهما إلى جانب `stat unit` و`stat memory` في قبول الأداء.

## مشهد القياس الثابت

يجب تنفيذ اللقطة من خريطة `/Game/Maps/Rok2Main`، بعد دخول لاعب موثق وظهور طبقة العالم. يبدأ القياس بعد استقرار اللقطة مدة خمس ثوانٍ. تُشغّل الكاميرا بالتتابع على طبقات **Tactical** ثم **Regional** ثم **Kingdom**؛ ويحفظ المراجع لقطة `GetPerformanceSnapshot()` في نهاية كل نافذة مدة 60 ثانية.

| المقياس | المصدر | لماذا يُلتقط |
|---|---|---|
| زمن راسم العالم المتوسط والقمة | `GetPerformanceSnapshot()` | يكشف تراجع دورة عرض العالم نفسها |
| المدن والممرات والعقد | عدادات HISM في اللقطة | يثبت تكلفة العناصر المجمّعة لا actors منفردة |
| markers والمسيرات والتلال | عدادات الراسم في اللقطة | يرصد التوسع في العناصر المتحركة أو الخاصة |
| المسبح الخامل | `PooledMarkerActors` | يثبت إعادة الاستخدام بدلاً من churn عند تحديث اللقطات |
| زمن الإطار وGame/GPU | `stat unit` | معيار قبول الإطار الكلي على الجهاز |
| الذاكرة | `stat memory` و`stat RHI` | معيار قبول الذاكرة والـRHI على الجهاز |

## ميزانية القبول الأولية

هذه الحدود **أهداف قبول للمراجعة الداخلية** وليست نتيجة قياس منشورة؛ لا يجوز إعلان تحقيقها قبل حفظ سجل الجهاز والحزمة والمشهد.

| المسار | الهدف الأولي | ما يعنيه الفشل |
|---|---:|---|
| معدل الإطار في المشهد، على جهاز Android المستهدف | 30 FPS كحد أدنى مستقر | يفتح تحقيقاً في زمن CPU/GPU قبل رفع كثافة العالم |
| زمن إطار اللعبة الكلي المتوسط | 33.3 ms أو أقل | لا يمر المشهد إذا كان متوسط 60 ثانية أعلى من الحد |
| زمن `Tick` لراسم العالم المتوسط | 4.0 ms أو أقل | يراجع تكوين markers والتحديثات قبل تغيير جودة الرسم |
| زمن `Tick` لراسم العالم القمة | 12.0 ms أو أقل | تراجع spikes الناتجة عن refresh أو تحريك المسيرات |
| عناصر HISM وactors | يسجل العدد الفعلي، لا حد مصطنع | تقارن اللقطات بين الإصدارات قبل تعديل السعة أو الأصول |

## إجراءات القياس

ابدأ نافذة نظيفة باستدعاء `ResetPerformanceSnapshot()` على كائن `ARok2WorldRenderer`. بعد خمس ثوانٍ من الاستقرار، نفذ حركة الكاميرا المحددة وأبق المشهد 60 ثانية في كل طبقة تكبير. التقط ناتج `GetPerformanceSnapshot()`، ثم شغّل `stat unit` و`stat memory` و`stat RHI` وسجل اسم الجهاز، build، دقة العرض، وطبقة التكبير.

عند تراجع القياس، افحص أولاً تغير عدد `MarkerActors` أو `MarchActors` أو عقد HISM. تحافظ الشفرة الحالية على HISM للعناصر الكثيفة وعلى `URok2Perf` لمسبح markers؛ لا تستبدلها بزراعة actors منفردة لمعالجة مشكلة بصرية. إذا كان القيد GPU أو الذاكرة، يصحح القرار من إعدادات العرض أو الأصول بعد تسجيل السبب، لا بتعديل أرقام ميزانية اللعب.

## حارس التراجع

يشغل الأمر التالي الحارس البنيوي ضمن البوابة العادية:

```bash
cd game/backend
npm run test:world-performance-budget
npm run check
```

يتحقق الحارس من وجود عدادات القياس، HISM، pooling، وإعدادات Android التي تحفظ المسار المتنقل البسيط. لا يقيس FPS أو الذاكرة؛ لا يمكن الحصول على هذه القيم بصورة موثوقة من حارس Node خارج Unreal ومن دون جهاز Android.

## شرط الإغلاق

يبقى P7-T6 مفتوحاً إلى أن ينفذ مراجع واحد على الأقل المشهد أعلاه في حزمة Development مبنية بـ UE 5.4.4 وعلى جهاز Android المستهدف، ويحفظ نتائج الطبقات الثلاث مع اسم الجهاز، ورقم الالتزام، وقيم الإطار والذاكرة. عندئذ فقط تقارن النتائج بميزانية القبول وتوثق نتيجة PASS أو خطة معالجة.
