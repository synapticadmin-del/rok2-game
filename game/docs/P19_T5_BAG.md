> الحارس: `game/backend/scripts/items_bag_offline_test.mjs` — 88 فحصاً.

## 1. العطل الأكبر لم يكن غياب الشاشة

خمسة مواضع في `KingdomShard` تكتب:

```ts
INSERT INTO player_inventory (player_id, day_key, key_id, amount)
ON CONFLICT(player_id, day_key, key_id) DO UPDATE SET amount=amount+excluded.amount
```

**وتلك أعمدة لا وجود لها.** الجدول في `migrations/0005_shop.sql`:

```sql
CREATE TABLE IF NOT EXISTS player_inventory (
  player_id TEXT NOT NULL,
  item_id TEXT NOT NULL,
  count INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL,
  PRIMARY KEY (player_id, item_id)
);
```

ولا هجرة في المشروع تُضيف `day_key` — تحققتُ: `grep -rn day_key migrations/`
يعيد صفراً.

وكل إدراج مغلّف بـ`.catch(() => undefined)`، فالفشل **صامت تام**: اللاعب يفتح
صندوقاً في الحانة، يرى النتيجة في الاستجابة، يُحدَّث سجل الرميات وعدّاد
anti-cheat — **ولا يدخل شيء حقيبته أبداً**.

المواضع الخمسة: الحانة، متجر ميداليات Expedition، متجر رموز Canyon، عجلة
الأحداث، ومتجر المملكة المفقودة.

### والمعرّفات لم تكن معرّفات عناصر

```ts
`tavern:${playerId}:${dayString(now)}:${rollResult.rolls.length}`   // مفتاح رمية!
`canyon_token_${bought.item.id}`
`expedition_medal_${result.item.id}`
`lk_${String(key)}`
`wheel_${kind}`
```

فلو نجح الإدراج لظهر للاعب سطرٌ لاتيني مركّب بلا اسم ولا أيقونة ولا وصف.

## 2. العطل الثاني: لا حقيبة أصلاً

`/v1/shop/catalog` يعيد المخزون كخريطة عارية:

```ts
const inventory: Record<string, number> = {};
for (const r of invRows.results || []) inventory[r.item_id] = r.count;
```

بلا اسم ولا أيقونة ولا فئة. وعلى العميل:

```cpp
void ARok2GameMode::HandleItemsAction()
{
    if (Api) Api->EmitToast(TEXT("الحقيبة قيد التجهيز — ستظهر العناصر هنا عند توفرها"));
}
```

وزر «حقيبة» في عنقود الـHUD موجود منذ P5-T3 — أي أن اللاعب يملك عناصر من
المتجر والمهام وBattle Pass ولا سبيل له إلى رؤيتها ولا استخدامها.

## 3. الحل

### `data/items.json` — الفهرس السلطوي

17 عنصراً في خمس فئات (تسريع/مفاتيح/قادة/مواد/معزّزات). كل عنصر: اسم عربي،
وصف، أيقونة من مكتبة الأيقونات الإجرائية، نُدرة 1..5، قابلية استخدام، والشاشة
التي يُستخدم فيها.

والتسريعات السبعة **ثوانيها مطابقة لكتالوج المتجر** — يحرسه الفحص، فلا نسختان
لرقم واحد.

### التطبيع يحفظ التوافق

```ts
export function normalizeItemId(rawId: string): string
```

يترجم المفاتيح التاريخية الست (`expedition_medal_*`, `canyon_token_*`,
`lk_sculpture_shards`, `lk_speedups_8h`, `sculptureShards`, `materials`,
ومفتاح رمية الحانة) إلى معرّفات الفهرس. **الغرض التوافق لا التجميل**: صفوفٌ
كُتبت قبل هذا البند تُقرأ صحيحة بدل أن تُحذف.

وما لا يُعرف **يبقى كما هو** — لا اسم مخترع.

### الدمج بعد التطبيع

منحوتات القادة تأتي من ثلاثة مصادر بمفاتيح مختلفة. لو بقيت سطوراً منفصلة لظهر
للاعب ثلاثة أرصدة لعنصر واحد. `buildInventoryView` يدمج ثم يرتّب بالفئة فالنُدرة،
والمجهول آخراً.

### مسار منح وحيد

```ts
private async grantInventoryItem(playerId: string, rawItemId: string, amount: number)
```

بأعمدة الجدول الصحيحة، والفشل **يُسجَّل** في عدّادات P7-T15:

| الرمز | متى |
|---|---|
| `inventory_grant_failed` | فشل الإدراج فعلاً |
| `inventory_unknown_item:<id>` | معرّف خارج الفهرس (يُمنح لكن يُرى) |

فعطلٌ في الجدول يظهر في `/ops` لا في شكوى لاعب.

### الشاشة

`URok2BagWidget`: تبويبات **من فئات الخادم** لا قائمة محلية (إضافة فئة في JSON
تظهر بلا تعديل عميل)، والفئة الفارغة من العناصر تُطوى لأن تبويباً بلا محتوى
يستهلك لمسة بلا مقابل. وحافة كل صف بلون نُدرته من `Rok2Visual::RarityTier`.

## 4. ثلاثة قرارات صدق

**`bLoaded` يفصل «فارغة» عن «لم تُقرأ».** الشاشة لا تقول «حقيبتك فارغة» قبل
وصول اللقطة — تقول «جارٍ قراءة الحقيبة…».

**`known:false` يُقال صريحاً.** العنصر الذي لا يعرفه فهرس الخادم يُعرض بمعرّفه
ووصفه «عنصر لا يعرفه فهرس الخادم — يُعرض بمعرّفه». عطلٌ يجب أن يُرى لا أن يُخفى
تحت اسم عام.

**غير القابل للاستخدام يُسمّى شاشته.** «يُستخدم في الحانة» · «في شاشة القائد» ·
«في المعدات» — بدل زر معطّل بلا تفسير.

## 5. الاستخدام يمرّ بالمسار القائم

`UseBagItemOnQueue` تستدعي `/v1/shop/use-speedup` الموجود — لا endpoint استخدام
ثانٍ يكرّر منطق الخصم. وتعيد قراءة الحقيبة والمدينة بعده، فلا خصم محلي متوقَّع
(AGENTS.md §3 «الخادم هو السلطة»).

وهدف التسريع هو **أول طابور نشط**: اختيار الطابور من قائمة ثانية يجعل الفعل ثلاث
لمسات، وقاعدة §8.1 تحدّه بثلاث من شاشة المدينة. وإن لم يوجد طابور فتوست صادق
(«لا طابور نشط لتسريعه») لا صمت.

| `npm run check:ue-contracts` | أخضر بالكامل (62 حارساً) |

ما يحرسه الفحص تحديداً:

- **منع عودة الأعمدة القديمة** في الكود (لا في التعليقات — توثيق العطل مفيد).
- **كل معرّف مُشار إليه** في `daily_quests.json` و`tavern.json` و
  `battlepass.json` معروف في الفهرس — فمكافأة بمعرّف مجهول تفشل الفحص لا تظهر
  سطراً بلا اسم.
- تطابق ثواني التسريع مع كتالوج المتجر.
- المواضع الخمسة كلها تمرّ بالمسار الوحيد (≥ 5 استدعاءات).
- **فصل وسائط التبويبات عن وسائط الصفوف**: `RebuildItems` تُنادى وحدها عند
  تبديل التبويب، ومصفوفة مشتركة تعني أن تفريغها يُتلف أزرار التبويبات.
- لا نص عربي في `items.ts` — أي اسم فيه يعني نسخة ثانية من الاسم.
