# P7-T3 — رحلة لاعبين E2E من البداية إلى الممر

**الوثيقة:** `game/docs/P7_T3_TWO_PLAYERS_E2E.md` | **الحارس:** `verify_p7_t3_journey.mjs` | **الـ job:** `test:e2e-p7-t3` في `npm run check`

<!-- الحارس: test:e2e-p7-t3 job runs the full path (E2E_FULL=1) -->

## ما يثبته الاختبار

يجري `game/backend/scripts/e2e_p7_t3_player_journey.mjs` رحلة كاملة للاعبين جديدين على خادم محلي نظيف (D1 + Durable Objects معزولان، الهجرات تُطبّق تلقائيًا، ثم يُزال كل شيء):

| # | الخطوة | الطلب | الإثبات |
|---|--------|-------|---------|
| 0 | جاهزية الخادم | `GET /v1/health` | 200 و`ok` |
| 0 | مؤشرات التشغيل والخصوصية الإدارية | `GET /v1/admin/ops` بلا رمز ثم بمفتاح الإدارة | رفض 401/403 للطلب المجهول، ثم snapshot صالح يتضمن health status، طوابع tick، زمن tick، أخطاء الأوامر، الطوابير، التنبيهات وسجل الأخطاء |
| 0 | الخصوصية | `GET /v1/world/snapshot` بلا رمز | رفض 401/403 — لا بيانات عالم دون مصادقة |
| 1 | تسجيل ضيف | `POST /v1/auth/guest` ×2 (روما/الصين) | رمز موقع موقع بأمان لكل لاعب |
| 2 | FTUE | `POST /v1/city/init` | تأسيس مدينتين بحضارتين مختلفتين |
| 3 | عالم مشترك | `GET /v1/world/snapshot` | المدينتان جديدتان في نفس اللقطة |
| 4 | تحالف | `POST /v1/alliance/create` ثم `join` | عضوية مرئية للطرفين |
| 5 | منحة موارد | `POST /v1/admin/grant` (admin key) | موارد وقوات اختبارية فقط |
| 6 | رالي على ممر | `POST /v1/alliance/rally` (pass) | حالة `forming` ومساهمات منفصلة |
| 7 | رؤية الرالي | `GET /v1/alliance/rallies` | ظاهر للعضو قبل وبعد الانضمام |
| 8 | إعادة تحميل الجلسة | إعادة `GET /v1/alliance/rallies` | `isJoined=true` دون تكرار عضوية (إعادة الاتصال) |
| 9 | إطلاق خادمي | `forceTicks` بعد `launchMs` | الحالة `launched` + `march_id` موحد |
| 10 | الوصول والقتال | تذاكر خادمية + لقطة لكل لاعب | تقرير قتال **لكل من الزعيم والمشارك** بخسائر الهجوم والدفاع |
| 11 | قصة الموسم | اللقطة | معلم `first_pass_capture`/`pass_conquered` |
| 12 | العودة | تذاكر إضافية | المسير يختفي من `marches` بلا خطأ مفتاح أجنبي — القوات تعود للمالكين |

## التشغيل

```bash
# المسار الكامل تلقائيًا في بيئة معزولة (اختبار الجودة):
npm run test:e2e-p7-t3

# المسار السريع (تكوين + ملكية + استرجاع) على خادم يدوي:
ADMIN_KEY=... E2E_LIVE=1 BASE_URL=http://127.0.0.1:8787 node scripts/e2e_p7_t3_player_journey.mjs

# المسار الكامل (إطلاق + قتال + قصة موسم) على خادم يدوي:
ADMIN_KEY=... WAIT_FOR_RALLY=1 E2E_LIVE=1 BASE_URL=http://127.0.0.1:8787 node scripts/e2e_p7_t3_player_journey.mjs
```

**ملاحظة E2E:** مدة التجمع الرسمية `rally.prep_seconds = 300` ثانية في `zones.json` — طويلة جدًا لاختبار آلي. في وضع المعزول الكامل يُختصر مؤقتًا إلى 8 ثوانٍ قبل إقلاع الخادم (لأن `zones.json` يُجمَّع داخل العامل) وتُستعاد القيمة الأصلية في `teardown` حتى لو فشل الاختبار. على خادم يدوي (`E2E_LIVE=1`) لا يُعدَّل أي ملف؛ إن أردت المسار الكامل سريعًا عدّل `prep_seconds` يدويًا ثم أعده.

**ملاحظات بروتوكول:** `wrangler dev` يقرأ `.dev.vars` عند الإقلاع فقط؛ قاعدة D1 المحلية الافتراضية فارغة حتى أول `wrangler d1 migrations apply rok2-db --local`؛ السكربت المعزول يعالج كل ذلك تلقائيًا بنسخة جديدة من `.dev.vars` احتياطية مستردة.

## العلاقة ببند P7-T3 في PLAN.md

البند يشترط: مستخدمان جديدان، المدينة وFTUE، التحالف، الرالي/الممر، تقرير القتال، قصة الموسم، إثبات الملكية والخصوصية وإعادة الاتصال. كل بند من هذه البنود له سطر فحص مخصص في السكربت (51 فحصًا في المسار الكامل بعد إضافة شهادة ops)، والحارس البنيوي يطابق كل بند مقابل النص الحرفي للسكربت قبل تشغيله. وتتحقق الشهادة الجديدة من أن مؤشرات P7-T8/P7-T15 محمية إداريًا وتعيد حقولًا قابلة للاستخدام في runbook.

## ما لا يثبته الاختبار

لا يثبت هذا الاختبار قبول العميلين المستقلين في PIE (راجع `Docs/PIE_TWO_CLIENTS_ANDROID_ACCEPTANCE.md` في مجلد العميل) ولا سلوك WebSocket الحي في العميل — تلك معايير تُقبل على UE 5.4.4 في بيئة Windows.
