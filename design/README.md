# مرجع تصميم ROK2

> **هذا المجلد هو المرجع التصميمي المعتمد للإصدار التالي.** يشرح *لماذا* وكيف يجب أن تعمل الواجهة والخريطة والحضارات. أما القيم التي ينفذها الخادم والعميل فتظل في ملفات البيانات المصدرية؛ لا تُنسخ يدوياً في أكثر من مكان.

## خريطة مصادر الحقيقة

| المجال | مصدر الحقيقة التنفيذي | مرجع التصميم | طريقة التحديث | الحالة |
|---|---|---|---|---|
| الحضارات والوحدات والمزايا | `data/civilizations.json` | `02-civilizations/` | عدّل JSON ثم شغّل مولّد الملفات | منفذ جزئياً |
| القادة والمهارات وثوابت التقدم | `data/commanders.json` | `02-civilizations/` و`03-systems/POWER_MODEL.md` | عدّل JSON ثم شغّل مولّد الملفات | منفذ جزئياً |
| مستويات القوات | `data/troop_tiers.json` | `03-systems/POWER_MODEL.md` | عدّل البيانات ثم اختبر معادلة القوة | منفذ جزئياً |
| المباني المتاحة | `data/buildings.json` | `04-world-map/BUILDING_CATALOG.md` | حالة كل مبنى موثقة صراحة | منفذ جزئياً |
| ألوان ومكونات الواجهة | `Rok2VisualTheme.*` | `01-visual/VISUAL_IDENTITY.md` | أضف الرمز في C++ والوثيقة معاً | قيد التوحيد |
| الخريطة والتحالفات | قواعد الخادم وطبقة عميل الخريطة | `04-world-map/MAP_AND_ALLIANCE_INTERACTION.md` | وثّق العقد قبل التفعيل | تصميم معتمد |

## علامات حالة المحتوى

| العلامة | معناها |
|---|---|
| **[منفذ]** | له مسار بيانات/كود موجود ويمكن اختباره. |
| **[قيد الدمج]** | مواصفة معتمدة؛ يلزم ربطها بالعميل أو الخادم. |
| **[مقترح]** | خيار تصميمي غير ملزم لا يدخل الإنتاج قبل توازن وتنفيذ. |
| **[مرجعي قديم]** | محتوى تاريخي أو استكشافي؛ لا يستعمل كعقد بيانات. |

## أوامر الحماية من التعارض

```bash
# بعد تغيير الحضارات أو القادة فقط
node design/05-production/generate_roster_summary.mjs
node design/05-production/generate_civilization_files.mjs

# قبل دمج أي تغيير برمجي للخادم/العميل
cd game/backend && npm run check
```

لا يغير مولدا التصميم ملفات `data/`؛ هما يقرآنها فقط. لذلك تبقى مراجعة الأرقام في مكان واحد، بينما تكون الوثائق قابلة للتجديد في أي وقت.

## الوثائق التاريخية

تظل الملفات تحت `01-map/` و`02-civilizations/` و`07-game-design/` محفوظة للقراءة والخلفية. تحمل الملفات ذات المجال المتداخل إحالة صريحة إلى هذا المرجع بدلاً من أن تنافسه. لا تحذف التاريخ ولا تنسخ أرقامه إلى البيانات؛ صحح المصدر التنفيذي ثم أعد التوليد.

## قائمة مراجعة أي ميزة جديدة

| السؤال | الدليل المطلوب قبل الدمج |
|---|---|
| ما عقد البيانات؟ | معرّف ثابت وحقول موثقة في JSON أو API. |
| ما الحالة المرئية؟ | عادي، مرور، غير متاح، مختار، نجاح، وخطأ؛ مع نص/رمز لا لون فقط. |
| كيف تظهر في القوة؟ | بند معلوم في `POWER_MODEL.md` وتقرير قتال قابل للتفسير. |
| ما المقابل التكتيكي؟ | مسار أو مدى أو كلفة أو زمن يمنع التفوق غير القابل للرد. |
| هل تعمل على الهاتف؟ | هدف لمس مريح، نص قابل للقراءة، وحالة شبكة واضحة. |
